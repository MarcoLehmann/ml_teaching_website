Stochastic Gradient Descent Tutorial

The goal of this tutorial is to introduce the Gradient Descent algorithm and its variants. We assume you are familiar with Linear Regression and with the concept of the Mean Squared Error (MSE).

The machine learning problem

When solving a machine-learning problem, we always find four main 'ingredients': Data, Model, Cost (Loss), and the Optimizer. In this tutorial we focus on the optimizer and keep the other ingredients as simple as possible.

  • Data: We generate 2-dimensional points with a linear relationship and add Gaussian noise to them.
  • Model: We use a linear function (line equation) $\hat{y} = a \cdot x + b$ to predict the target variable $y$ for a new input $x$.
  • Cost (Loss): The goal is to minimize the Mean Squared Error (MSE).
  • Optimizer: We introduce an iterative optimization algorithm: Stochastic Gradient Descent (SGD)

The Data

We generate N data points sampled near the line $y = 0.3x + 0.5$ + Gaussian noise.

The Model

The goal of the model is to predict $\hat{y}$ for a new $x$. Here, we use a linear model: $\hat{y} = a \cdot x + b$.

Optimization and the Loss Function

Optimization algorithms aim to determine the input variables (here a and b) that minimize (or maximize) a specified objective function. In the context of machine learning, the objective function is typically called loss function. Other common terms are cost or error.

The loss function used in linear regression is the Mean Squared Error (MSE) (here divided by 2 for reasons that become clear later):

$$MSE = \frac{1}{2N}\sum_{i=1}^N (y_i - (a \cdot x_i + b))^2$$

The Intuition behind Gradient Descent

Imagine you place a ball anywhere on the landscape. The ball will roll down the slope of the landscape and stop at the location with the smallest error.

We can formulate this intuitive approach more technically:

We pick a starting point [a,b] randomly. Then we move a (small) step downhill. This is the direction in the parameter space where the error changes the fastest; mathematician call that direction the gradient. At the new location, we calculate again the gradient and make a small step. This procedure is repeated until a termination criteria is met.

This iterative procedure is, informally, the Gradient Descent algorithm. The method is efficient, because we do not perform a calculation at unnecessarily many location over the entire landscape.

The Gradient

For the Gradient Descent algorithm, we need the direction (in the a, b plane) of the fastest change (change of the loss). This direction is given by the vector of partial derivatives:

$$\text{Gradient of E} = \begin{bmatrix} \frac{\partial E}{\partial a} \\ \frac{\partial E}{\partial b} \end{bmatrix}$$

$$E = \frac{1}{2N}\sum_{i=1}^N (y_i - (a \cdot x_i + b))^2$$

💡 Solution: The Gradient of the MSE

$$ \begin{align} \frac{\partial E}{\partial a} &= \frac{1}{N}\sum_{i=1}^N (y_i - (a \cdot x_i + b)) (-x_i) \\ \frac{\partial E}{\partial b} &= \frac{1}{N}\sum_{i=1}^N (y_i - (a \cdot x_i + b)) (-1) \end{align} $$

Note: The factor 1/2 in the MSE is canceled by the factor 2 when calculating the partial derivatives.

💡 Comments

1) By definition, the gradient is a vector that points to the direction of fastest GROWTH. Following the gradient, we would move uphill, in the direction of increasing loss. For Gradient Descent we have to flip the sign of the vector.

2) The step is very large. When a step is too long, it may happen that instead of moving down the hill, we land on the other side of a valley where the loss is higher than at the starting point. The solution is to scale it down the length of the vector. The optimal scaling factor depends on the problem at hand. The scaling factor is typically called learning rate. Often the symbol $\alpha$ or $\eta$ is used to denote it.

3) The gradient is a vector that is orthogonal to the contour lines of the loss function.

4) The gradient provides information about the location (a,b). It does not point to the mimimum of the loss.

5) At the location of the optimal solution, (the minimum of the loss), the gradient vanishes.

A Single Gradient Descent Step

The gradient descent update rule defines how to update the parameter vector [a, b] in a single iteration:

$$ \begin{align} \begin{bmatrix} a \\ b \\ \end{bmatrix}_{t+1} = \begin{bmatrix} a \\ b \\ \end{bmatrix}_{t} - \alpha \begin{bmatrix} \frac{\partial E}{\partial a} \\ \frac{\partial E}{\partial b} \\ \end{bmatrix} \Big\rvert _{\begin{bmatrix} a \\ b \\ \end{bmatrix}_{t} } \end{align} $$

But what is Stochastic Gradient Descent?

Approximating the Gradient

In the example above, we used only a few data points. When evaluating the gradient of the loss function, we were taking into account all data. Imagine we were given $N=100'000$ datapoints. Then, at each iteration, we would have to iterate over all $N=100'000$ points to calculate the gradient of the loss function. This is computationally expensive. But ask yourself: how much would the gradient change, if we used only $N=99'999$ points? or $N=1'000$? or in the extreme case of $N=1$? Would the optimizer still move downhill?

The idea behind Stochastic Gradient Descent (SGD) is that we do not need the exact gradient to find a trajectory toward the minimum. Instead, at each iteration we can randomly pick a few datapoints and use them to calculate an approximation of the gradient (As long as we move more or less downhill, the algorithm still works). On average, over many iterations, the errors introduced by approximating the gradient, will average out. There is a trade-off: the algorithm needs more and shorter steps (because it takes some "detours"), but each step is computationally cheaper (faster).

The number of calculations needed to obtain the gradient vector is proportional to the number of data points $N$. We use the symbol $J_n$ to denote a set of $n$ indices, randomly chosen from the interval [1 N]. In the case of $n=1$ (a single randomly chosen index $j$), the equation simplifies:

$$ \begin{align} \textrm{E} &= \frac{1}{2N} \sum_{i=1}^{N} (y_i - (a \cdot x_i + b))^2 \\[20pt] \frac{\partial \textrm{E}}{\partial a} &= \frac{1}{N} \sum_{i=1}^{N} (y_i - (a \cdot x_i + b)) (-x_i) \\ &\approx \frac{1}{n} \sum_{j \in J_n} (y_j - (a \cdot x_j + b)) (-x_j) \\ \frac{\partial E_j}{\partial a} &= (y_j - (a \cdot x_j + b)) (-x_j) \\[20pt] \frac{\partial \textrm{E}}{\partial b} &= \frac{1}{N} \sum_{i=1}^{N} (y_i - (a \cdot x_i + b)) (-1) \\ &\approx \frac{1}{n} \sum_{j \in J_n} (y_{j} - (a \cdot x_{j} + b)) (-1) \\ \frac{\partial E_j}{\partial b} &= (y_{j} - (a \cdot x_{j} + b)) (-1) \end{align} $$

Stochastic Gradient Descent (SGD)

Unlike Gradient Descent, SGD does not use the true gradient but an approximation using a batch of randomly selected data points. The optimal batch size depends on many factors, for example on the model, the data, the hardware. A typical batchsize used to solve textbook examples is N=32. If a batch is much smaller than the original dataset, it is called minibatch. Only the extreme case of $N=1$ is called SGD by some authors. In practice, the terms Batch Gradient Descent and Stochastic Gradient Descent are used interchangeably.

The loss landscape of different batches

It can be confusing to see SGD jumping around (even moving uphill) while the error landscape looks smooth. The reason is that the error landscape shown above is not the same landscape actually used by SGD. At every iteration, SGD samples a different batch and therefore the error landscape is changing at each iteration. In other words even in SGD the vector always points downhill, but that error landscape is usually not visualized.
Here we fill that gap and visualize the error landscape for three different random subsets of the given data (random batches). Note that we add the same point (a0, b0) to each of the three figures and show the respective gradients.

Remember: The loss depends on the parameter and the data. Each time a different batches is sampled, the loss landscapes changes!

The plot illustrates that for different batches the gradient points to different directions. The gradient is exact with respect to the batch and points downhill in all 3 examples. When those vectors are drawn on the original landscape (using all data), it seems "as if the ball was not rolling downhill".

Stochastic Gradient Descent with annealed learning rate

We have seen that, for a fixed learning rate $\alpha$, SGD does not converge. Instead, the algorithm keeps fluctuating around the minimum. One can set $\alpha$ to a very small value, in which case the fluctuations are smaller and SGD stays 'close enough' to the minimum during the 'late iterations'. Therefore, in order to obtain a result of high accuracy, one would choose a very small $\alpha$. During the 'early iterations', the situation is different: There is no benefit staying close to the optimal trajectory. As long as SGD moves roughly in the direction toward the minimum, fluctuations (even relatively large ones) around the 'optimal' trajectory are acceptable. One would therefore choose a large $\alpha$ in order to improve the speed of the algorithm.
Annealing solves this appearent contradiction by adapting the learning rate. It starts with a large $\alpha$ and reduces it over time. There are many options (so called schedules) how one can reduce the learning rate over time. Here we decay the learning rate by multiplying it at each iteration by a decay factor: $\alpha_{t+1} = \max(\alpha_t \cdot \text{anneal}, \text{lower bound})$
